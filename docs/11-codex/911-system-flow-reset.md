# TOMP System Flow Reset

วันที่: 2026-07-29

## ปัญหาที่ต้องแก้

UI เดิมมีหลายหน้าใช้คำว่า test / pilot / driver / assignment ซ้ำกัน ทำให้ผู้ใช้ไม่รู้ว่าควรเริ่มตรงไหน และบาง flow สร้างข้อมูลได้แต่ใช้งานต่อไม่ได้ เช่น Assignment ที่ยังขาดคนขับหรือรถ แต่พยายามสร้าง QR ต่อ

## โครงสร้างการใช้งานใหม่

ระบบต้องมีเส้นทางหลักที่ชัดเจน 4 กลุ่ม

1. **ภาพรวม**
   - ใช้ดูสถานะรวมของระบบและทางลัดหลัก
   - ไม่ใช้เป็นหน้ากรอกข้อมูลเชิงลึก

2. **ทดสอบระบบจบขั้นตอน**
   - จุดเริ่มหลักสำหรับ internal pilot
   - ทำงานตาม flow: ตรวจระบบ -> สร้างโครงการทดสอบ -> เปิด QR คนขับ -> แชร์ GPS -> ดู Mission Control
   - หลีกเลี่ยงการกระจายปุ่มทดสอบไว้หลายหน้า

3. **ศูนย์ควบคุม**
   - ใช้ติดตามตำแหน่ง GPS, Assignment, ความเสี่ยง และ Timeline
   - ต้องตอบคำถามว่า “ใคร อยู่ในงานไหน สัญญาณสดหรือไม่ และต้องติดตามอะไร”

4. **พื้นที่วางแผน**
   - โครงการ, Assignment, ทรัพยากร
   - ใช้จัดเตรียมข้อมูลจริง
   - QR สร้างได้เฉพาะ Assignment ที่มี Call Sign, คนขับ และรถครบ

## เส้นทางทดสอบหลัก

1. เปิดหน้า `/live-test`
2. กด “เริ่มทดสอบระบบ”
3. ระบบตรวจตารางสำคัญใน Supabase
4. ระบบสร้างชุดข้อมูลทดสอบจริง
5. เปิดลิงก์คนขับบนมือถือ
6. คนขับกดเริ่มแชร์ GPS และอนุญาตตำแหน่ง
7. เปิด Mission Control เพื่อตรวจหมุดและสถานะ
8. ตรวจ Assignment เพื่อดู QR และสถานะงาน

## กฎ UX หลัง reset

- เมนูหลักต้องไม่พาผู้ใช้ไปหน้า demo หลายทางที่ทำหน้าที่เดียวกัน
- หน้าคนขับไม่ควรเป็นเมนูหลักสำหรับเจ้าหน้าที่ เพราะปกติต้องเข้าผ่าน QR
- หน้า admin ใช้ตรวจระบบ ไม่ใช่ flow ปฏิบัติการประจำวัน
- ข้อความ error ต้องบอกสิ่งที่ต้องแก้ ไม่แสดง error ดิบจากฐานข้อมูล
- ถ้าเป็นข้อมูลตัวอย่างหรือชุดทดสอบ ต้องระบุว่าเป็น “ข้อมูลทดสอบ”
